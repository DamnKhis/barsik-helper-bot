# Вопросы со скриншотами

Как бот обрабатывает картинку от пользователя, почему это не требует изменений в
RAG-ядре и как это связано с пакетом `bars-kb/dist`.

## Коротко

```text
текст  ─────────────────────────────► build_query(text, None) ════╗
                                                                    ╠══► Retriever.answer_query(<строка>)
фото ─► vision (qwen3.8-flash) ─► build_query(caption, описание) ═══╝        (Qdrant: dense + bm25, RRF)
```

Оба пути дают **обычную строку** и дальше идут одинаково. Для текстового вопроса
`build_query` возвращает текст без изменений, поэтому старый путь отвечает ровно
как раньше. Новых коллекций, векторов и зависимостей нет — `app/rag/` не меняется.

## Почему формат именно такой

Скриншоты уже проиндексированы при сборке базы знаний: чанки с
`chunk_type="screenshot"` содержат `description`, `ocr_text`, `ui_elements`,
а `raw_text`/`enriched_text` собраны по шаблону в
`bars-kb/src/bars_kb/chunker.py` (`_image_chunk`, `_join_enriched`).

Присланная картинка описывается **тем же промптом** (`PROMPT_VISUAL` из
`bars-kb/src/bars_kb/enrich/images.py`) и **той же моделью** (`qwen/qwen3.8-flash`),
после чего строка запроса собирается по тому же шаблону:

```text
Скриншот интерфейса БАРС-Офис. Вопрос пользователя: <подпись или «не указан»>

Изображение: <подпись или «скриншот из вопроса пользователя»>
<description>

Текст на изображении:
<ocr_text>

Элементы интерфейса:
- <label> (<location>)

Вопросы: <questions>
```

Так dense-эмбеддинг запроса оказывается рядом с эмбеддингами проиндексированных
скриншотов, а префикс «БАРС-Офис» не даёт фильтру оффтопа
(`Retriever._classify_intent`) отбросить картинку без подписи.

Ограничения: запрос обрезается до `vision.MAX_QUERY_CHARS` (3000) — длинный OCR
портит и эмбеддинг, и промпт LLM.

## Что происходит с присланным файлом

Файл **не удаляется**: он сохраняется в `IMAGE_QUERY_DIR/<telegram_id>/` и нужен
оператору — когда ИИ не может ответить, оператор в тикете должен видеть весь
диалог вместе со скриншотами. Путь к файлу уже сейчас кладётся в FSM-состояние
(`state["operator_images"]`) в момент эскалации; сама передача картинок в тикет —
следующий шаг, интерфейс для него готов.

Чистка: `IMAGE_QUERY_KEEP_DAYS` (по умолчанию 30 дней, `0` — вечно), лениво, один
раз за процесс.

## Ключи и настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `VISION_ENABLED` | `1` | `0` — отвечать только по подписи, без vision |
| `VISION_MODEL` | `QWEN_VISION_MODEL` → `qwen/qwen3.8-flash` | модель vision |
| `VISION_CACHE_DIR` | `data/vision_cache` | кэш разборов по sha256 картинки |
| `IMAGE_QUERY_DIR` | `data/query_images` | куда складывать присланные картинки |
| `IMAGE_MAX_MB` | `20` | лимит размера |
| `IMAGE_QUERY_KEEP_DAYS` | `30` | срок хранения (`0` — вечно) |
| `SEND_KB_IMAGES` | `0` | `1` — присылать найденный скриншот из БЗ вместе с ответом |

Ключ и base_url берутся из той же цепочки, что у RAG-ядра:
`LLM_API_KEY` → `QWEN_API_KEY` → `OPENROUTER_API_KEY`, `LLM_BASE_URL`. Один ключ
OpenRouter обслуживает эмбеддинги, генерацию ответа и vision.

## Деградация

| Ситуация | Поведение |
|---|---|
| `VISION_ENABLED=0` или нет ключа | поиск по одной подписи (если она есть) |
| Картинка без подписи и vision не ответил | бот просит описать вопрос текстом (не падает) |
| bars-kb недоступен (нет `PROMPT_VISUAL`) | то же, поиск по подписи |
| Qdrant недоступен | обычный путь: заглушка → эскалация на оператора |
| Ответ > 4096 символов | `_send_long` разбивает его по абзацам |

## Проверка

```bash
# юниты (без сети)
.venv/bin/python -m pytest app/tests/test_image_query.py -v

# оффлайн-проверка на реальных скриншотах дистрибутива: картинка → запрос → поиск
PYTHONPATH=bars-kb/src .venv/bin/python tools/check_image_query.py --limit 10
# то же с подписью пользователя и печатью собранного запроса
PYTHONPATH=bars-kb/src .venv/bin/python tools/check_image_query.py --limit 3 --caption "что это за окно?" --print-query
```

Скрипт берёт картинки из `bars-kb/dist/<build>/images/`, прогоняет их через
`vision → build_query → KB.search` и считает, попал ли поиск в чанк, из которого
эта картинка была взята (`hit@1`/`hit@3`). Низкий hit@1 — сигнал крутить шаблон
запроса, а не архитектуру.
