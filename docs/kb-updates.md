# Обновление базы знаний: как документ попадает в ответы

Коротко про путь «документ → ответ» и про то, как проверить, что он действительно
прошёл. Появилось после разбора ситуации «PDF добавляли — отвечал, DOCX добавляли —
молчал».

## Путь документа

```text
Админ → «Добавить доку» → uploaded_docs/<файл>
      → kb_autosync.stage_document() → bars-kb/docs/source/<файл>
      → watcher (bars-kb watch) видит новый digest → пересобирает пакет
      → bars-kb/dist/<build_id> + dist/LATEST
      → бот читает LATEST на каждом поиске (kb_client) → отвечает
```

Важно: пересборка идёт по **всей** папке `docs/source`, поэтому если она прошла
успешно, в сборке оказываются все лежащие там документы. Если в базе нет нового
документа — значит пересборка не прошла (или не запускалась), а не «документ
не разобрался».

## Почему это раньше не было видно

Админ получал «Пересборка запустится автоматически в течение 60 с» и всё.
Пересборка могла не запуститься или упасть по причинам, которые в чате не видны:

| Причина | Что происходит | Как проявляется |
|---|---|---|
| нет `QWEN_API_KEY` | `bars_kb.cli` отказывается публиковать mock/hash-сборку и выходит с кодом 2; watcher умирает | в логе приложения `KB autosync остановился с кодом 2` |
| не поднят Qdrant | сборка падает после обогащения, `dist/` не меняется | `watch: rebuild failed, will retry: ... Connection refused` |
| приложение запущено из каталога без `.env` | тот же отказ mock/hash | «KB autosync не запустился» |
| `KB_AUTOSYNC=0` | watcher не стартует | в ответе админу сказано «запустите bars-kb sync вручную» |
| документы лежат не в той папке, которую смотрит watcher | digest не меняется | пересборки нет вообще |

Во всех случаях бот продолжает отвечать из **предыдущей** сборки. Вопросы, чьи
темы пересекаются со старыми документами, получают ответ, а новые темы
(например, «Пропуск», которого в старых PDF нет вообще) — нет.

## Что теперь делает бот

`app/bot/services/kb_status.py` показывает правду о пакете:

* `snapshot()` — какая сборка в `dist/LATEST`, сколько документов и чанков, какой
  digest исходников в неё зашит (digest считается той же формулой, что в
  `bars_kb.pipeline.source_fingerprint`);
* `status.stale` — папка с документами новее сборки, то есть часть документов
  ещё не пересобрана;
* `status.has_document("БП Пропуск.docx")` — есть ли конкретный файл в сборке.

Поэтому после загрузки документа админ видит:

```text
Документ добавлен в базу знаний: БП Пропуск.docx
Текущая сборка — сборка 20261114T205237_a5023733: документов 3, чанков 102.
Этого документа в сборке пока нет.
Пересборка запустится автоматически в течение 60 с — сообщу, когда документ окажется в базе.
```

а затем одно из двух (таймаут — `KB_CONFIRM_TIMEOUT_SEC`, по умолчанию 900 с):

```text
✅ Документ в базе знаний: БП Пропуск.docx
сборка 20261115T224248_1e01c5cb: документов 5, чанков 132.
Регламент можно спрашивать прямо сейчас.
```

```text
⚠️ Документ «БП Пропуск.docx» пока не попал в базу знаний.
Похоже, пересборка не прошла: папка с документами новее сборки 20261114T205237_a5023733.
Проверьте лог приложения (KB autosync) и что Qdrant поднят, либо запустите bars-kb sync вручную.
```

То есть «документ добавлен» больше не означает «документ в базе».

## Проверка без запуска бота

```bash
# 1. что вообще есть в пакете (список сборок, звёздочка — актуальная)
PYTHONPATH=bars-kb/src .venv/bin/python -m bars_kb.cli builds

# 2. манифест актуальной сборки: документы и чанки
PYTHONPATH=bars-kb/src .venv/bin/python -m bars_kb.cli status

# 3. статус так, как его видит бот (stale + наличие файла)
PYTHONPATH=.:bars-kb/src .venv/bin/python -c "
from app.bot.services import kb_status
s = kb_status.snapshot()
print(s and s.short(), '| stale:', s and s.stale)
print('документы:', s and s.document_list())
"

# 4. пересобрать вручную, если watcher спит
PYTHONPATH=bars-kb/src .venv/bin/python -m bars_kb.cli sync --source bars-kb/docs/source
```

## Про DOCX отдельно

Формат разбирается штатно: у «БП Пропуск.docx» получается 18 чанков (13 текстовых,
4 таблицы, 1 схема бизнес-процесса, 1 изображение). Поиск по ним работает — проверено
на реальных эмбеддингах:

| Вопрос | Источник в ответе |
|---|---|
| «Как оформить пропуск и кто согласовывает заявку?» | `БП Пропуск > 5 Инструкция > 5.4 Оформление и выдача пропуска` |
| «Сколько времени занимает проверка службой безопасности?» | `БП Пропуск > 5.3 Проверка Службой безопасности` |

Слова «пропуск» нет ни в одном другом документе (в трёх старых PDF — 0 вхождений,
в «Справочнике БАРС-Офис» — тоже 0), так что при вопросе про пропуск поиск
обязан попадать в чанки docx — если он вообще в сборке.

Отдельная просьба к будущим правкам: у «Справочника БАРС-Офис» распознаётся всего
одна секция (заголовки не детектятся), поэтому в цитатах у него нет пути раздела.
