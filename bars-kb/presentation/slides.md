# BARS KB
## Документация → чистый датасет в Qdrant

**Наша часть:** ingestion, структура чанков, эмбеддинги, Qdrant, handoff
**Не наша часть:** Telegram-бот, генерация ответов, API, эскалация

---

# Задача и границы

**Надо:** превратить 3 PDF-документа БАРС в воспроизводимый Qdrant-датасет,
который следующий разработчик подключает к своей модели.

**Сделано:**
- парсинг PDF/DOCX/MD/TXT;
- очистка Word/PDF-мусора;
- чанкинг с breadcrumb и parent/child;
- dense + sparse (BM25) в Qdrant;
- экспорт с векторами и скрипт восстановления;
- offline-метрики на 13 контрольных вопросах.

**Не сделано намеренно:** HTTP API, бот, ответы пользователю.

---

# Архитектура

```text
PDF / DOCX / MD / TXT
        │
        ▼
  parsers/  ── заголовки, списки, таблицы, изображения
        │
        ▼
  clean/    ── футеры Word, колонтитулы, оглавление
        │
        ▼
  chunker/  ── text | table | image | FAQ, parent/child
        │
        ▼
  enrich/   ── Qwen3.8-Flash: текст, JSON, таблицы, скриншоты
        │
        ▼
  embeddings/ ── dense 1024 + BM25 sparse
        │
        ▼
  Qdrant: bars_kb_<build> → alias bars_kb_current
        │
        ▼
  dist/: chunks.jsonl.gz + images + config + restore
```

# Структура чанка

| Поле | Зачем |
|---|---|
| `chunk_id` | стабильный UUID (v5) |
| `doc_id`, `doc_title` | документ |
| `section_path` | путь раздела для цитаты |
| `page` | страница PDF |
| `chunk_type` | `text`, `faq`, `table`, `diagram`, `screenshot` |
| `raw_text` | оригинал — только для цитаты |
| `enriched_text` | по нему ищем: breadcrumb + summary + вопросы |
| `parent_id`, `parent_text` | контекст раздела для LLM |
| `source_url` | ссылка на документ и версию |
| `image_path` | скриншот/схема |
| `version`, `content_hash` | версионирование и дедуп |

**Принцип:** ищем по обогащённому тексту, отвечаем по `raw_text`.

# Что было сложным в документах

- **Word-футеры:** `Ошибка! Используйте вкладку "Главная"...` — вычищены.
- **Оглавление PDF:** строки с `.... 12` — отброшены.
- **Таблицы PDF:** Word-экспорт теряет границы колонок → PDF-таблицы не структурируем,
  DOCX-таблицы парсим структурно.
- **Скриншоты:** 41 изображение; без vision-ключа получают контекстное описание,
  с Qwen-VL — OCR, элементы интерфейса, выноски.
- **Схема БП:** 1 diagram-чанк с Mermaid-представлением.
- **Точные строки:** `!> 200`, `2334-26`, длинные URL — закрыты sparse BM25 + FAQ-слоем.

---

# FAQ-слой: только из источника

Для сложных вопросов добавлены FAQ-чанки, **собранные из текста документов**:

- почему не работает `!> 200` → поддерживаются `>`, `<`, `=`, `!=`;
- сделка `2334-26` со статусом 30% → нужен порог воронки;
- запуск БП без бюджета → автоматическая проверка средств;
- график офис-менеджеров;
- «реестр техники» → в базе есть только «реестр мебели», честно сообщаем об этом.

Это не выдуманные ответы, а сжатые цитаты + маршрутизация к разделу.

# Handoff следующему разработчику

```text
dist/<build_id>/
├── chunks.jsonl.gz          # id + dense + sparse + payload
├── images/                  # 42 файла
├── images.jsonl             # chunk → image
├── documents.jsonl          # документы и версии
├── collection_config.json   # схема коллекции
├── manifest.json            # counts, модель, checksums
├── sparse_vocab.json        # словарь BM25
└── eval_report.json         # метрики и примеры выдачи
```

- `examples/restore_from_export.py` — залить в Qdrant;
- `examples/query.py` — пример hybrid-поиска;
- `examples/reembed_from_export.py` — пересчитать dense-векторы под чужую модель;
- `bars-kb sync` — пересборка, `bars-kb sync --github` — из репозитория;
- alias `bars_kb_current`, предыдущая версия — `bars_kb_prev`.

# Обновление и отказоустойчивость

- Каждая сборка — **новая коллекция** `bars_kb_<build_id>`.
- Alias переключается атомарно: `current`, старая — `prev`.
- Ошибка пересбора **не ломает** текущую версию.
- Локально: положить файлы в `docs/source` → `bars-kb sync`.
- GitHub: `bars-kb sync --github` по cron / GitHub Actions, без webhook-сервера.
- Полный пересбор — осознанно: документов мало, зато нет «дрейфа» частичных обновлений.

# Ограничения и что дальше

**Ограничения:**
- без ключа Qwen скриншоты описаны контекстно, без OCR;
- PDF-таблицы не структурированы;
- embedded Qdrant не делает snapshot → основной формат `chunks.jsonl.gz`.

**Что делаем при появлении ключей:**
1. `.env`: заполнить `QWEN_API_KEY` (остальное уже указывает на Qwen3.8-Flash).
2. `bars-kb ingest` — пересбор с реальными описаниями и эмбеддингами.
3. Проверить визуальные чанки и повторить eval.

**Согласовано со следующим разработчиком:**
генерация — `qwen3.8-flash`, эмбеддинги — Qwen `text-embedding-v4`, dim 1024.
Один провайдер и один `QWEN_API_KEY`. Вектор запроса обязан считаться той же
embedding-моделью, что и коллекция. Если модель изменится — `examples/reembed_from_export.py`.
