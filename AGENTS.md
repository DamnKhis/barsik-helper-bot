# AGENTS.md — правила работы для людей и ИИ-агентов

Этот файл читают все: участники команды и любые ИИ-агенты (Cline, Claude Code,
Roo Code и т.п.), запущенные в репозитории. Правила одинаковые для всех.

## 1. Контекст проекта (не переписывать, а дополнять)

- Продукт: Telegram-бот первой линии поддержки по документации «БАРС-Офис».
- Цепочка: вопрос → поиск по Qdrant → ответ LLM с «Источник: …, раздел …» →
  при низкой уверенности честное «не знаю» + эскалация с историей.
- Стек: Python 3.11, FastAPI, aiogram 3, Qdrant, Redis, SQLite, Docker.
- Документация — **PDF**; парсинг: PyMuPDF (основной), pdfplumber (таблицы-фолбэк),
  pytesseract (OCR сканов), скриншоты подписывает VLM. Менять парсер можно только
  с сохранением контракта `list[Block]` (`indexer/blocks.py`).
- LLM и эмбеддинги — любые OpenAI-совместимые (DeepSeek / GLM / OpenAI /
  Ollama+bge-m3). Провайдер меняется только через `.env`, не в коде.

## 2. Контракт API (менять только всем вместе, одним коммитом)

`POST /ask` — запрос (`app/schemas.py`):

```json
{
  "text": "Как считается аванс за командировку?",
  "user_id": "123456789",
  "history": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]
}
```

Ответ:

```json
{
  "answer": "Аванс рассчитывается как (Дата по − Дата с) × 700 …",
  "sources": [{"doc": "БП Командировка.pdf", "section": "2.3 Аванс", "link": null, "score": 0.83}],
  "confidence": 0.83,
  "escalate": false
}
```

- `escalate: true` → бот предлагает оператора. Решение принимает только ядро
  (`app/rag/confidence.py`), бот его не дублирует.
- Новые поля добавлять опциональными, чтобы не ломать чужую часть.

## 3. Схема чанка в Qdrant

```json
{"text": "Документ: … | Раздел: …\n<текст>", "doc": "имя файла", "section_path": "2.3 Аванс", "link": ""}
```

- Чанки режутся по заголовкам, таблица не отрывается от своего раздела
  (`indexer/chunking.py`).
- Поле `doc` — ключевое для переиндексации: удаление точек идёт по нему.

## 4. Границы ответственности

| Модуль | Владелец | Чужим не трогать |
|---|---|---|
| `indexer/` | Роль 1 | — |
| `app/rag/`, `app/schemas.py`, `app/main.py` | Роль 2 | — |
| `bot/` | Роль 3 | — |
| `app/analytics/`, `app/integrations/`, `app/static/`, `qa/`, CI | Роль 4 | — |

Нужное изменение в чужом модуле — задача в Issues/чат, не прямой коммит.

## 5. Ветки и мержи

- Ветка на задач: `role1/parsing-vlm`, `role2/reranker`, `role3/escalation-ui`…
- В `main` мержит только интегратор (роль 4), после `make lint && make test`.
- Мелкие правки чужих файлов без логики (импорты после рефакторинга) — можно.

## 6. Стиль кода

- ruff (`make lint`) обязан проходить: `line-length 110`, сортировка импортов.
- Комментарии и тексты для пользователя — по-русски; идентификаторы — по-английски.
- Все настройки — через `settings.py` и `.env`; секреты в код не класть.
- Любая новая логика покрыта хотя бы smoke-тестом (`app/tests/`, `indexer/tests/`).

## 7. Железные правила качества (критерии жюри)

1. Ответ всегда содержит «Источник: <документ>, раздел <раздел>» — иначе фрагмент
   считается браком.
2. Нет данных в базе → честное «не нашёл», НИКОГДА не выдумывать факты, цифры,
   названия кнопок.
3. Эскалация всегда несёт вопрос + историю диалога.
4. Перед коммитом гонять свой вопрос из `qa/test_cases.csv` и обновлять в нём
   колонки «Факт» и «Статус».

## 8. Definition of Done по ролям

- Роль 1: `make index` индексирует все три PDF; в коллекции нет дублей при
  повторном запуске; таблицы попадают в чанки целиком; скриншоты превращаются
  в подписи (VLM) или плейсхолдер с сохранённым файлом.
- Роль 2: все «базовые» и «подвохи» из `qa/test_cases.csv` проходят; порог
  уверенности откалиброван так, что вопрос вне базы стабильно даёт «не знаю».
- Роль 3: приветствие/кнопки по брифу; «оператор» ловится по тексту и кнопкой;
  тикет содержит историю; бот корректно переживает недоступность API.
- Роль 4: дашборд показывает метрики брифа + «слепые зоны»; поллинг Git реально
  переиндексирует после пуша; CI зелёный; README и демо-скрипт актуальны.
